# 固件 v3-auto：去掉写死的设备身份，改为运行时自动识别

- 新固件：`firmware/cmcc_s3_bridge_v3auto_20261029_0051/`
- 旧固件：`firmware/cmcc_s3_bridge/`（**原样保留，未改动，md5 `9f43a994944bd9374db778329a849242`**）
- 编译：`esp32:esp32:esp32s3:USBMode=default,CDCOnBoot=cdc`，Arduino-ESP32 3.3.12
- 结果：695141 字节（53% Flash），静态内存 65608 字节（20%）

---

## 一、删掉了什么

旧版把"某一台遥控器"的身份写死在三个常量里：

| 位置 | 旧写法 | 问题 |
|---|---|---|
| `TARGET_NAME` | 广播名精确等于某个字符串 | 这只遥控器**根本不广播名字**（`adv3.txt` 里 `name=''`），这条从没生效过 |
| `TARGET_ADDR` | MAC 地址常量 | 换一只遥控器直接失效，且无法在运行时改 |
| `payloadIsRemote()` | 广播里搜 ASCII `LY RC` | 是讯飞某一批的厂商标记，其他型号没有 |

v3 里这三处全部消失。现在整个文件搜不到任何具体遥控器的名字、MAC 或厂商字符串。

另外删掉两处"隐性写死"：

- 订阅列表 `const uint8_t want[] = {0x01, 0x03}` —— 写死了键盘和消费者报告的 id
- 分发判断 `reportId == 0x01 / 0x03 / 0xFC` —— 写死了各报告的含义

## 二、换成了什么

### 1. 发现：广播包打分，取最高分

候选条件全部来自广播包本身或 NVS 配置，命中任意一条即可参选：

| 条件 | 分数 | 是否默认启用 | 说明 |
|---|---|---|---|
| 地址与 NVS 里记住的一致 | 100 | 是 | 上次连上过的设备，最可靠 |
| 广播名前缀匹配 | 40 | 仅在配置了 `npfx` 时 | 给设备起名规整的场景用 |
| 厂商 ID 匹配 | 30 | 仅在配置了 `cid` 时 | `0xFF` 厂商数据前两字节，蓝牙 SIG 分配 |
| Appearance ∈ `0x03C0~0x03C4` | 25 | 是 | HID 通用/键盘/鼠标/摇杆/手柄，**这是本机能被认出来的关键** |
| 广播含服务 UUID `0x1812` | 25 | 是 | 另一类 HID 设备的常见广播方式 |
| 任意可连接设备 | 1 | 否（`any=1` 才开） | 最后手段 |

AD 结构是逐条遍历解析的（`adFind()`），不假设字段顺序、不假设有哪些字段。

### 2. 连接：用广播里的真实地址，并自动记住

地址优先级：`NVS 里记住的` > `广播里报的`。

连上并成功订阅后，自动把该地址写进 NVS（`autopin=1`，默认开），下次开机直接按地址认，不再依赖广播特征。

只有一种情况拿不到地址：设备做定向广播时协议栈可能上报 `00:00:00:00:00:00`。此时固件不会乱连，而是提示用 `TARGET xx:xx:xx:xx:xx:xx` 手工指定一次——之后同样会自动记住。

### 3. 报告：读 HID Report Map 描述符，自动分类

连接后读 `0x2A4B`（Report Map），跟踪 `Usage Page` / `Report ID` / `Report Size` / `Report Count`，记录每条 report 所属的**顶层集合**与累计位数，然后按规范含义分类：

| 顶层集合 | 单帧字节数 | 判定 | 动作 |
|---|---|---|---|
| Generic Desktop `0x01` / Keyboard `0x06` | 任意 | 键盘 | 订阅，按「修饰键 + 6 键码」解析 |
| Consumer `0x0C` | 恰好 2 | 消费者 | 订阅，按 16 位 usage 解析 |
| Consumer `0x0C` | 很长（如 255） | 数据通道 | **不订阅** |
| 其他（鼠标、厂商自定义） | — | 忽略 | 不订阅 |

第二条的「长度」是必要条件：这只遥控器的 `0xFC`、`0xFB`、`0xF9`、`0xF8` 在描述符里**也是 Consumer 页**，与 `0x03` 同页同类型，只能靠位数区分。旧版靠写死 `0xFC` 名字来排除它，v3 靠规范里的位数来排除。

### 4. 兜底：读不到描述符就退回老规则

若 `0x2A4B` 读不到（例如链路未加密）或解析出 0 条 report，则退回「只订 `0x01` 键盘、`0x03` 消费者」的旧逻辑。这条路径的代码行为与旧版完全一致。

## 三、新增串口命令

| 命令 | 作用 |
|---|---|
| `CFG` | 打印当前识别条件 |
| `CFG pin=<mac>` / `npfx=<前缀>` / `cid=<hex>` / `any=<0\|1>` / `autopin=<0\|1>` / `app=<0\|1>` / `hidu=<0\|1>` | 改条件，可一次给多个，立即存 NVS |
| `CFG RESET` | 识别条件恢复默认（不影响映射表） |
| `TARGET` | 查看：记住的地址、当前候选、分数、命中原因 |
| `TARGET <mac>` | 手工指定地址（定向广播上报全 0 时用） |
| `TARGET CLEAR` | 清掉记住的地址，回到自动发现 |
| `MAPDUMP` | 打印 Report Map 原文十六进制 + 每条 report 的分类结果 |

`INFO`、`LIST`、`SET`、`DEL`、`SAVE`、`LEARN`、`RAW` 等原有命令与输出格式**未改动**，设置端 exe 不需要改。

启动日志新增两行，换设备时看这两行就能判断卡在哪：

```
# 识别条件 pin=- npfx=- cid=0000 any=0 autopin=1 app=1 hidu=1
# Report Map: 224 字节，解析出 7 条 report
#   id=0x01 type=1 h=0x0032 notify=1 role=键盘 bytes=8
```

## 四、验证情况

**已验证**：用这只遥控器真实的 224 字节描述符（本机 `report_map.bin`）跑同一套分类算法，输出如下，与旧版写死的行为完全一致：

```
id=0x01 page=0x01 usage=0x06 bytes=  8 -> 键盘    【订阅】
id=0x02 page=0x01 usage=0x02 bytes=  4 -> 忽略    （鼠标，不订阅）
id=0x03 page=0x0C usage=0x01 bytes=  2 -> 消费者  【订阅】
id=0xF8 page=0x0C usage=0x01 bytes=255 -> 数据    （不订阅）
id=0xF9 page=0x0C usage=0x01 bytes=255 -> 数据    （不订阅）
id=0xFB page=0x0C usage=0x01 bytes=255 -> 数据    （不订阅）
id=0xFC page=0x0C usage=0x01 bytes=255 -> 数据    （不订阅）
```

**未验证**（必须上机才知道）：

1. 实际能否读到 `0x2A4B`。它是一条约 224 字节的长特征值，如果链路加密状态不允许读，会走兜底路径——功能不受影响，但自动分类不生效。
2. 打分策略在**多台 HID 设备同时在场**时的实际表现。默认靠 Appearance 认，附近如果有别人的蓝牙键盘，存在连错的可能；连错一次就会被 `autopin` 记住，需要 `TARGET CLEAR` 清掉。
3. 换一只不同型号遥控器后，它的描述符是否也是这套结构。

---

## 五、回滚

新固件是独立的 sketch 目录，旧固件一个字节没动。烧回旧版只要编译烧录 `firmware/cmcc_s3_bridge/` 即可。

NVS 里新增的键是 `cmcc_map/dev`，与映射表 `cmcc_map/binds` 互不影响；回退到旧固件后这个键会被忽略，映射表照常读取。
