# 故障排查

按「现象 → 原因 → 处理」组织。没列到的请开 issue，附上串口日志（`RAW 1` / `SCANDUMP 1` 的输出）。

---

## 1. 设备管理器报「该设备无法启动（代码 10）」

**这是本项目存在的原因，不是故障。** Windows 蓝牙栈（`mshidumdf`）严格校验 HOGP 的
Report Reference 与 Report Map，这只遥控器 9 个 Report 里有 3 个对不上，校验直接拒绝初始化。

不要在 Windows 蓝牙里折腾驱动、不要用「删除设备重新配对」，都不会好。走本项目的链路：
ESP32 收按键 → USB HID 输出。原理见 [architecture.md](architecture.md)。

## 2. exe 被 Smart App Control 拦

现象：双击 `CMCC_RC_Keys.exe`，弹「智能应用控制已阻止可能不安全的应用，因为无法验证其发布者」，
只有「正常」和「从 Microsoft Store 获得应用」两个按钮，**没有「仍要运行」**。

### 不是键盘钩子的问题

Smart App Control（SAC）在**进程创建之前**就做判定，属于内核态策略，程序的代码一行都没执行。
键盘钩子只是普通 Win32 API（`SetWindowsHookEx`），不在任何黑名单里。

### 实测：它按文件哈希查云端信誉

| 实验对象 | SHA256 前缀 | 结果 |
|---|---|---|
| 一个能正常跑的旧 exe（原文件） | `ddd2621d` | 能跑 |
| 同一个文件改名 + 换目录 | `ddd2621d` | 能跑 |
| 同一个文件改 1 个填充字节 | `efbcfbe8` | **被拦** |
| 本项目新打包的 exe | `28e87a34` | 被拦 |
| 自签名（已导入受信任根） | 又不同 | **仍被拦** |

结论：**只认文件哈希**，不看路径、不看文件名、不看签名者是否受信任。未知哈希 → 送微软云端信誉库
（ISG）→ 没有记录就拦。相关注册表：`VerifiedAndReputablePolicyState=1`，事件日志 Event ID 3077。

所以自签名证书对自己本机**没有帮助**（对别人的机器也没有，除非证书链被系统广泛信任且积累信誉）。

### 三条可行路径

1. **用 `pc\run.bat` 或 `pythonw remote_ui.pyw` 启动**（推荐）
   python 本身是微软签名的受信任程序，加载脚本不受 SAC 管辖，双击即用、零成本。
2. **自己打包一次**：换哈希并不能绕过（新哈希还是未知），这条只在**目标机器已关闭 SAC** 时有效。
3. **买代码签名证书**：OV 约 ¥1200/年、EV 约 ¥2500/年（2026 年参考价，Certum/GlobalSign/Sectigo 等）。
   EV + 累积下载量之后才可能进信誉库，不是买了立刻免拦。

关闭 SAC 不可逆（微软明确说明关掉后无法重新开启，只能重装系统），不建议为这个程序关闭。

## 3. 串口打不开 / 提示被占用 / 端口号变了

| 现象 | 原因 | 处理 |
|---|---|---|
| `could not open port 'COM10': PermissionError` | 被残留句柄占着（上次没退干净的 `python.exe`、串口助手、Arduino 串口监视器） | 换一个 COM 号，或结束占用进程 |
| 扫不到端口 | 插的是 UART 口不是 OTG 口；或线是纯充电线 | 换口、换线 |
| 端口号每次插拔都变 | Windows 的正常行为 | 点「扫端口」重新列一遍 |

实测踩过 **COM10 被残留句柄占着、换 COM11 立刻正常**，不是驱动问题，也不是固件问题。

## 4. 遥控器一直连不上

按这个顺序排：

1. **`TARGET_ADDR` 是不是你的遥控器**？`SCANDUMP 1` 看广播里的地址，逐字符核对；
2. **按一下遥控器任意键再等 10 秒**。这只遥控器按键唤醒后只广播很短一段时间，冷着扫不到；
3. **别让手机/电视同时连着它**。HOGP 通常只接受一个主机，别的设备占着就轮不到 ESP32；
4. 日志里连续 `# 连接失败` → `REBOOT` 一次再试；
5. 看到 `# !! 没发现 0x1812` 或 `# !! 0x1812 下看不到特征` → 链路没加密成功，
   通常是配对信息残留：在手机/Windows 上删除该设备的配对，再用 ESP32 连。

## 5. 某些键没反应

先分清是「键没上报」还是「映射空」：

```text
→ RAW 1          # 打印原始通知
（按键）
← # RAW h=0x0025 id=0x01 len=9 | 00 00 04 ...
```

- **有 `# KEY <id> ...` 但 `map=NONE`** → 这个 id 没有映射。`SET` 一条即可，id 直接从日志抄；
- **有 RAW 但没有 KEY** → 帧解析没认出来，把 RAW 行贴到 issue 里；
- **连 RAW 都没有** → 这个键在蓝牙侧不发数据，见下条。

### TV 键

**物理上无解。** 同一个 600 秒抓包窗口内，音量 + 正常上报 `E9 00 → KEY 20E9`，
TV 键按 3 次零帧（连空白报告都没有）。遥控器固件把 TV 键直接交给了红外发射管，
蓝牙链路里根本没有这个键。要控制电视只能用原遥控器的红外。

### 语音（麦克风）通道

现状：录音键只映射成 `Win+H`（唤起 Windows 语音键入，用**电脑**麦克风）。

遥控器自带麦克风的私有通道（service `0x6287`、report `0xFC`）没解开：
订阅后遥控器会主动断链，抓到的音频也不是标准 IMA ADPCM（熵 7.35 bit/sample）。
`tools/hci/experiments/` 里留了复现脚本和当时的分析结论，欢迎接着挖。

## 6. 录键时 Win+L 把电脑锁屏了

Win+L 是 Windows 的安全保留动作：`WH_KEYBOARD_LL` 能收到 `VK_LWIN` 和 `0x4C`、
也能拦住 L 键不让它进别的程序，但**拦不住「Win 按下 + L → 锁工作站」这个判定**——
判定发生在钩子之外，这是有意的安全设计（否则任何程序都能劫持锁屏）。

对比：Win+D（回桌面）、Win+E（资源管理器）、Alt+Tab 都能正常拦，因为它们只是普通 shell 热键。

能挡住 Win+L 的只有一条路：把当前用户的「锁定工作站」策略置 1。

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System
    DisableLockWorkstation = 1   (DWORD)
```

生效是**即时**的（不用重启、不用注销），删除即恢复。但这个键在受保护的 `\Policies\` 分支下，
**非管理员写入一律 `WinError 5 拒绝访问`**（实测：普通 HKCU 键可写，`\Policies\` 下全部拒绝）。

所以弹窗里给了两个出口：

| 按钮 | 行为 | 代价 |
|---|---|---|
| 直接填 Win+L | 不按键盘，直接把 `Win+L` 填进去 | 无（推荐） |
| 管理员屏蔽 Win+L | 弹一次 UAC，提权助手写策略，关窗自动还原 | 弹 UAC；屏蔽期间遥控器电源键也不锁屏 |

还原有三重保险：关弹窗立即还原、助手 5 分钟超时兜底、主程序启动时检查残留标记文件再还原。
即使主程序被强杀，也不会把你机器永久停在「不能锁屏」状态。

## 7. 按键输出不对 / 组合键顺序乱

- 组合键按下顺序 = `keys[]` 顺序，抬起是逆序。`SET` 时**修饰键要写在前面**：
  `SET 1066 1 2 E3 0F`（Win 在前，L 在后）；
- 修饰键 usage：`E0` Ctrl、`E1` Shift、`E2` Alt、`E3` Win（左），`E4`–`E7` 是对应的右键；
- 消费者键要 `outType=2`，且 16 位 usage 低字节在前：音量 + 是 `E9 00`，不是 `00 E9`；
- 不确定就 `LEARN 1` 打 id、`RAW 1` 看原始帧，别猜。
